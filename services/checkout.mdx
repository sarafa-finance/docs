---
title: "Hosted checkout"
description: "Create a fixed-amount payment link and read its payment status."
openapi: "/api-reference/openapi.json POST /checkout"
---

Create a single-payment invoice priced in USD. Hosted checkout supports card, Sarafa, and KES/UGX mobile payments. Link creation itself does not move funds or produce a payment callback.

```json
{
  "amount": "25",
  "currency": "USD",
  "title": "Order 100",
  "description": "Payment for your order",
  "reference": "order-100",
  "callback_url": "https://merchant.example/payments",
  "redirect_url": "https://merchant.example/orders/100"
}
```

`redirect_url` is optional. It must use HTTPS without embedded credentials. All other fields above are required. Checkout creation does not accept a `quote` field.

Example response, HTTP `201`:

```json
{
  "status": "success",
  "checkout": {
    "slug": "<generated-slug>",
    "title": "Order 100",
    "description": "Payment for your order",
    "amount": "25",
    "currency": "USD",
    "status": "open",
    "created_at": "2026-10-30T10:00:00.000Z",
    "reference": "order-100",
    "checkout_url": "https://checkout.sarafa.site/p/<generated-slug>",
    "transactions": []
  }
}
```

Redirect the payer to the returned `checkout_url`. Successful payment closes the link to further payments; failed attempts can be retried. Each attempt has its own `tx_reference` while retaining your checkout reference.

## Check checkout status

Use your merchant reference with `GET /v3/checkout/{reference}`:

```bash
curl "https://api.sarafa.site/v3/checkout/order-100" \
  -H "Authorization: Bearer $SARAFA_API_KEY"
```

Returns HTTP `200` with the same checkout response shape, including associated transactions. An unknown checkout reference within your organization returns HTTP `404`.

| Checkout status | Meaning |
| --- | --- |
| `open` | Available for payment. |
| `paid` | Successfully paid; further payments are closed. |
| `closed` | Closed without a successful payment. |

Browser redirects are not proof of payment. Confirm the outcome using this authenticated status read, [payment details](/api-reference/endpoint/getTransaction), or [signed callbacks](/services/api).
